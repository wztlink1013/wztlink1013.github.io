<p>[!NOTE]</p>
<p>在进行GitHub项目开发过程中，途中会有一些新想法，遇见的新bug等问题，提出的一些新灵感等等都可以利用GitHub每个项目自带的issues（议题）来进行管理、跟踪并且加以解决。传统的软件项目管理还有Milestones（里程碑）、Projects（画板）来一并进行项目的开发，GitHub在2020年还新增加了Discussion（讨论区）模块，进一步提高软件项目的管理工作。</p>
</blockquote>

<h2 id="issue标签类型总结">Issue标签类型总结</h2>
<h3 id="github默认标签">GitHub默认标签</h3>
<p><strong>Label</strong></p>
<p><strong>explanation</strong></p>
<p><strong>Description</strong></p>
<p>bug</p>
<p>提出一个bug</p>
<p>Indicates an unexpected problem or unintended behavior</p>
<p>documentation</p>
<p>添加/改进/详查文档</p>
<p>Indicates a need for improvements or additions to documentation</p>
<p>duplicate</p>
<p>重复的问题/requests/讨论</p>
<p>Indicates similar issues, pull requests, or discussions</p>
<p>enhancement</p>
<p>增强/新增功能</p>
<p>Indicates new feature requests</p>
<p>good first issue</p>
<p>好的想法/灵感</p>
<p>Indicates a good issue for first-time contributors</p>
<p>help wanted</p>
<p>过程中需要帮助</p>
<p>Indicates that a maintainer wants help on an issue or pull request</p>
<p>invalid</p>
<p>没有意义，不再讨论</p>
<p>Indicates that an issue, pull request, or discussion is no longer relevant</p>
<p>question</p>
<p>请提供进一步资料</p>
<p>Indicates that an issue, pull request, or discussion needs more information</p>
<p>wontfix</p>
<p>不做处理</p>
<p>Indicates that work won't continue on an issue, pull request, or discussion</p>
<h3 id="自需添加">自需添加</h3>
<p>debugging</p>
<p>正在调试</p>
<p>fixed</p>
<p>已被修复</p>
<h2 id="discussion的新革新">Discussion的新革新</h2>
<p>传统的流程是提出issues之后，根据不同的issue来跟进画板（Project）的内容。</p>
<p>上面的做法其实有一个思维上的bug，一些灵感之类的不好放上去，使用Discussion之后，可以在Discussion里面放上想法、灵感等，实际开发从这里面的一个的一个具体的评论转换到实际的issue里面</p>
