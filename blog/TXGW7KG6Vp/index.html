手把手教你搭建Hermes Agent并且配置微信和TG通知渠道完善日常工作流

尼采般地抒情·2026-05-22·4 分钟

前言：本文记录Hermes Agent和Coding Agent (Cursor, Claude Code, CodeX)的各司其职，先讲述Hermes Agent和Coding Agent的异同，然后记录个人在VPS中搭建一个Hermes Agent并且设置微信和Telegram两个通知渠道，完善个人日常工作流。

Hermes Agent和Coding Agent

个人工作流层面，superpowers、AGENTS.md等Harness Engineering在Coding Agent（Cursor/Claude Code/ CodeX）里写代码。OpenClaw / Hermes 不写代码——只做调研归纳、竞品扫描、会议/碎片整理、文档、灵感。

之前两三个月主用 OpenClaw + Discord，多个agent 分工收集。

痛点是：过程看不清、同类调研每次重讲背景。于是

最近打算切 Hermes Agent，并刻意换习惯验证：

  • Hermes + Telegram + MiMo（百亿 Token 活动额度 ++https://100t.xiaomimimo.com/++，扛长对话调研）
  • OpenClaw + Discord 收成搜集哨，不再扩新 agent
  • 后续场外 core 专门深耕 Hermes

关键判断：OpenClaw和Hermes属于++「信息与认知劳动」++；写代码另有战场，Cursor、Claude Code、CodeX。别混成一个工具期望，++不要想着用Hermes写代码，个人不建议这么做，因为具体实操起来还是很不方便，并且很浪费token。++

怎么选 + 收束

  • 要整理、记忆、可审计 → 先 Hermes Agent
  • 要多路并行盯梢 → 先 OpenClaw
  • 要写代码改仓库 → Cursor / CodeX / Claude Code + 项目约束

三条收束：① 非编码任务用固定 IM 做 1h A/B；② 编码 IDE、归纳 Hermes、搜集可留 OpenClaw；③ 选定 core 后别双主场扩 agent。
