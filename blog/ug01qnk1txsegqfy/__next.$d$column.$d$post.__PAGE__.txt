<h3 id="1-react-的-diff-算法">1. <strong>React 的 Diff 算法</strong></h3>
<p>React 使用了一种 <strong>O(n)</strong> 复杂度的 Diff 算法，这被称为 <strong>Fiber</strong>。该算法主要分为两部分：<strong>reconciliation（调和过程）</strong> 和 <strong>rendering（渲染过程）</strong>。</p>
<h4 id="核心思想">核心思想</h4>
<ul>
<li><strong>分层比较（树分层比较）</strong>：React 不会进行整个虚拟 DOM 树的逐个节点对比，而是将树分为不同层，逐层进行比较。这大幅降低了时间复杂度。</li>
<li><strong>组件类型不同，直接替换</strong>：如果新旧虚拟 DOM 的类型不同（比如 <code>&#x3C;div></code> 换成了 <code>&#x3C;span></code>，或者是不同的组件类型），React 不会去做深入比较，而是直接删除旧节点，创建新节点。</li>
<li><strong>key 优化</strong>：React 使用 <code>key</code> 属性来标识列表中的节点。当同级列表元素的 <code>key</code> 发生变化时，React 会尝试优化节点的重排，而不是逐个删除和重建。没有 <code>key</code> 的列表会引发性能问题，因为 React 会进行位置的逐个比对。</li>
</ul>
<h4 id="更新流程">更新流程</h4>
<ol>
<li>React 会从根节点开始比较每一层的虚拟 DOM。</li>
<li>如果节点类型相同（如 <code>&#x3C;div></code> 对比 <code>&#x3C;div></code>），则对比其属性和子节点。</li>
<li>如果节点类型不同，则直接删除旧节点，创建新节点。</li>
<li>对于列表，React 会优先查找 <code>key</code> 值相同的节点，避免不必要的删除和创建。</li>
</ol>
<h4 id="优化策略">优化策略</h4>
<p>React 的算法设计思路是通过 <strong>浅层对比</strong> 来加速渲染，优先保证渲染性能，而不是精确地对每个节点进行深层次比对。</p>
<h3 id="2-vue-的-diff-算法">2. <strong>Vue 的 Diff 算法</strong></h3>
<p>Vue 2 和 Vue 3 都使用了 <strong>O(n)</strong> 的 Diff 算法，核心基于 <code>snabbdom</code> 的实现，特别是在 Vue 3 中，diff 算法进行了优化，追求高效且轻量的更新过程。</p>
<h4 id="核心思想-1">核心思想</h4>
<ul>
<li><strong>双端比较</strong>：Vue 采用了 <strong>双端比较</strong> 策略，即分别从新旧虚拟 DOM 的两端进行对比，直到遇到不同的节点。这样可以快速确定相同的节点，减少中间节点的比对。</li>
<li><strong>patch 函数</strong>：Vue 使用 <code>patch</code> 函数递归地比较新旧虚拟 DOM 树，通过 <strong>最小化修改</strong> 的方式更新真实 DOM。</li>
<li><strong>静态节点优化</strong>：Vue 会在模板编译时对静态节点进行标记，这样在更新时可以跳过对静态节点的比对，从而提高性能。</li>
<li><strong>key 优化</strong>：和 React 类似，Vue 也会使用 <code>key</code> 来优化列表的节点更新，确保节点重用和位置变化的高效处理。</li>
</ul>
<h4 id="更新流程-1">更新流程</h4>
<ol>
<li>Vue 会从根节点开始对比新旧虚拟 DOM。</li>
<li>对比节点类型和属性：</li>
</ol>
<ul>
<li>如果节点类型不同，直接替换。</li>
<li>如果节点类型相同，则继续比较属性和子节点。</li>
</ul>
<ol start="3">
<li>如果是列表，Vue 会基于双端比较算法对列表进行最小化的更新操作。</li>
<li>对于静态内容的优化，Vue 会跳过不必要的更新。</li>
</ol>
<h4 id="vue-3-的优化">Vue 3 的优化</h4>
<ul>
<li><strong>编译阶段优化</strong>：Vue 3 在模板编译阶段会标记哪些部分是静态的，这样在更新时，Vue 可以直接跳过这些静态部分，进一步提升性能。</li>
<li><strong>更轻量的结构</strong>：Vue 3 引入了 Proxy 和更简洁的响应式系统，使得状态更新过程更高效，和 Diff 算法配合得更好。</li>
</ul>

<p>特性</p>
<p>React</p>
<p>Vue</p>

<p>O(n) 的 Fiber 架构，按层次比较</p>
<p>O(n) 的双端比较，使用 snabbdom 的 patch</p>
<p>key 优化</p>
<p>通过 key 优化列表更新</p>
<p>同样使用 key 来优化列表的节点重用</p>
<p>静态节点优化</p>
<p>通过 diff 对比逐层更新</p>
<p>编译时标记静态节点，跳过不必要的更新</p>
<p>更新策略</p>
<p>分层比较，不同类型节点直接替换</p>
<p>双端比较，动态跳过不必要的更新</p>
<p>性能侧重点</p>
<p>浅层快速对比，提升性能</p>
<p>通过最小化修改和静态节点优化提升性能</p>
