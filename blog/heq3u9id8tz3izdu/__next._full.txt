<h3 id="uselayouteffect">useLayoutEffect</h3>
<ul>
<li>useEffect：渲染并绘制到屏幕之后执行，异步</li>
<li>useLayoutEffect：渲染之后，但绘制到屏幕之前执行，同步</li>
<li>一般如果回调函数中有DOM的相关操作并且会改变样式，用后者，避免DOM渲染闪屏/白屏，但前者性能方面更好</li>
</ul>
<h1 id="渲染优化">✨渲染优化</h1>
<p>首先明确react组件重渲染的触发条件：</p>

<h2 id="1️⃣非渲染层面-组件结构设计">1️⃣【非渲染层面】 组件结构设计</h2>
<h3 id="分离组件和状态">分离组件和状态</h3>
<ul>
<li><strong>拆分组件</strong>：将大组件拆分成多个小组件，每个小组件只关注自己需要的状态。这可以减少状态变化时影响的范围，避免整个大组件的重新渲染。</li>
<li><strong>提升状态</strong>：如果多个组件共享同一份状态，可以考虑将状态提升到它们的共同祖先组件，然后通过 props 传递状态。</li>
</ul>

<h4 id="为什么要避免匿名函数和对象">为什么要避免匿名函数和对象？</h4>
<p>每次组件重新渲染时，JavaScript 会重新创建这些匿名函数和对象。这些新创建的函数和对象在内存中是不同的，即使它们的内容相同。这会导致以下问题：</p>
<ol>
<li><strong>导致子组件不必要的重新渲染</strong>： 当子组件接收到新的匿名函数或对象作为 props 时，即使这些 props 的内容没有变化，React 仍然认为这些 props 发生了变化，因为它们是新的引用，进而导致子组件重新渲染。</li>
<li><strong>性能问题</strong>： 频繁创建新的函数和对象会增加内存使用和垃圾回收的负担，尤其是在组件频繁更新的情况下，这会对性能产生负面影响。</li>
</ol>
<h3 id="usememo和usecallback">useMemo和useCallback</h3>
<p>React函数式组件在重新渲染时候，代码执行会将函数体重新执行，即便结果不是重新更新DOM。如果函数体的代码逻辑复杂会带来不小的性能损耗，如果能够对这过程中的部分“量”进行“记忆”，则会较大提升性能。</p>
<p>响应式变量内部会自动进行记忆，但是如果是非响应式变量，比如一个对象或是一个函数传入组件，这其实也是改变了的，原因是对象的引用改变，依然会引起组件的重新渲染，而利用useMemo或是useCallback创建的对象（对象、数组、函数）则会保留记忆功能。</p>

<h3 id="批量状态更新">批量状态更新</h3>
<p>批量更新是指 React 将多次 state 更新进行合并处理，最终只进行一次渲染，以获得更好的性能。</p>
<p>例如，如果在同一个点击事件中有两个状态更新，React 总是会把它们批量处理成一个重新渲染。</p>
<p>从 React 18 的 createRoot 开始，不论在哪里， 所有更新都将自动进行批量更新。</p>
<p>这意味着 setTimeout、promises、原生事件处理函数或其他任何事件的批量更新都将与 React 事件一样，以相同的方式进行批量更新。</p>
<p>比如下面这个组件，在React 18之前会渲染两次，但是React 18可以自动批处理</p>

<h2 id="并发模式">并发模式</h2>
<ol>
<li>React18之前，渲染是一个单一的、不间断的、同步的事务，一旦渲染开始，就不能被中断</li>

</ol>
