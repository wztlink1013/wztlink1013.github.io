12:T2dc7,<p>前言：前段时间写了一篇《手把手教你搭建Hermes Agent并且配置微信和TG通知渠道完善日常工作流》的技术分享。最近我习惯用 Hermes 的多 Agent 配合Hermes Kanban推进工作，Hermes Dashboard支持拖拽分配任务与自动调配，成了日常各类工作的调度中心。面板默认只监听本机 9119，不同设备访问不便，如果暴露公网不安全，如果通过SSH本地连接转发那么在不同设备访问不便。<strong>++本文记录用 Cloudflare Tunnel 与 Access 实现安全公网访问的完整方案：零入站端口、自动 HTTPS、邮箱白名单安全认证。++</strong></p>
<h2 id="背景为什么要把-dashboard-暴露到公网">背景：为什么要把 Dashboard 暴露到公网</h2>
<p>最近一段时间，我的工作流有明显变化：<strong>更依赖 Hermes 的多 Agent 协作，并用 Kanban 看板把任务串起来。</strong></p>
<p><img src="https://assets.musecanto.com/uvxwY7KW9sGYbUfSojyke/sv-books/2026_06_01_editorimg_88a19b35-9dc8-4086-b6db-213c0bdf07fe.png" alt="image" loading="lazy" decoding="async">大致是这样用的：</p>
<ul>
<li>多个 Agent 各司其职（调研、实现、验证等），由 Hermes 统一调度；</li>
</ul>
<p><img src="https://assets.musecanto.com/uvxwY7KW9sGYbUfSojyke/sv-books/2026_06_01_editorimg_1bb8a32d-211f-41b7-a2e3-bbd164a742a4.png" alt="image" loading="lazy" decoding="async"></p>
<ul>
<li><strong>Kanban</strong> 负责可视化：待办、进行中、阻塞、完成，一眼看清全局；</li>
<li><strong>Hermes Web Dashboard</strong>（本地默认 <strong>9119</strong> 端口）把会话、模型、定时任务、技能等集中管理。</li>
</ul>
<p>对我来说，Dashboard 不只是「看一眼状态」的页面，而是<strong>操作台</strong>：在看板上<strong>拖拽</strong>就能做任务分配，配合 Hermes 的调度能力还能做<strong>自动调配</strong>——比纯 CLI 直观得多，也更适合多 Agent 并行时的日常指挥。</p>
<p>问题是：Dashboard 默认只监听 <strong>localhost</strong>，人不在 VPS 旁时，手机、笔记本都访问不到。传统做法要开端口、Nginx、证书、认证，维护成本高。我需要的是：<strong>偶尔从外网安全打开这块看板</strong>，而不是再搭一套公网架构。</p>
<blockquote>
<p><strong>当本地服务已经是日常中枢（而不只是调试页）时，「安全公网可达」就变成刚需；Cloudflare Tunnel + Access 适合这种「轻量、个人、要强认证」的场景。</strong></p>
</blockquote>
<h2 id="一方案概述与流量路径">一、方案概述与流量路径</h2>
<p>目标：在<strong>不开放任何入站端口</strong>、<strong>不部署 Nginx</strong> 的前提下，通过 HTTPS 访问 Dashboard，并限制只有本人能登录。</p>
<p>流量路径：</p>
<div class="code-block"><pre><code class="hljs language-text">用户浏览器
  → Cloudflare Edge（HTTPS + Access 认证）
    → Cloudflare Tunnel（QUIC 加密隧道）
      → 服务器 cloudflared（本地进程）
        → http://localhost:9119（Hermes Dashboard）
</code></pre><button type="button" class="code-copy" data-copy-code="" aria-label="复制代码"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.5" aria-hidden="true"><rect x="8" y="8" width="12" height="12" rx="2"></rect><path d="M16 8V4a1 1 0 0 0-1-1H4a1 1 0 0 0-1 1v11a1 1 0 0 0 1 1h4"></path></svg><span>复制</span></button></div>






























<table><thead><tr><th>对比项</th><th>传统公网暴露</th><th>本方案</th></tr></thead><tbody><tr><td>防火墙</td><td>需开放端口</td><td><strong>零入站端口</strong></td></tr><tr><td>反向代理</td><td>通常需要 Nginx/Caddy</td><td><strong>不需要</strong></td></tr><tr><td>TLS 证书</td><td>自行申请与续期</td><td>Edge <strong>自动 HTTPS</strong></td></tr><tr><td>访问控制</td><td>自装 Basic Auth 等</td><td><strong>Cloudflare Access</strong> 策略</td></tr></tbody></table>
<blockquote>
<p>本质是把「公网访问我的端口」改为「本机进程主动向外建立隧道」，对 NAT、安全组、家庭宽带都更友好。</p>
</blockquote>

<h2 id="四创建-cloudflare-tunnel">四、创建 Cloudflare Tunnel</h2>
<p>在控制台创建，SSH 环境不宜依赖 <code>cloudflared tunnel login</code> 弹浏览器，callback 经常失败。建议在控制台创建 Tunnel 后，用 token 安装服务。</p>
<p>操作入口：</p>
<p><a href="https://one.dash.cloudflare.com/" rel="noopener noreferrer">https://one.dash.cloudflare.com/</a></p>
<p>路径：<strong>Networks → Tunnels → Create a tunnel</strong>，类型选 <strong>Cloudflared</strong>，命名（如 <code>hermes-dashboard</code>），安装方式选 <strong>Command line</strong>，复制 <strong>token</strong>给AI注入。</p>
<p><img src="https://assets.musecanto.com/uvxwY7KW9sGYbUfSojyke/sv-books/2026_06_01_editorimg_45dc1e88-c14c-44a6-9a4d-9dec30b6f379.png" alt="image" loading="lazy" decoding="async"></p>
<p>在服务器执行（可以直接让AI来做）：</p>
<div class="code-block"><pre><code class="hljs language-bash"><span class="hljs-built_in">sudo</span> cloudflared service install &#x3C;你的-token>
<span class="hljs-built_in">sudo</span> systemctl start cloudflared
<span class="hljs-built_in">sudo</span> systemctl <span class="hljs-built_in">enable</span> cloudflared
</code></pre><button type="button" class="code-copy" data-copy-code="" aria-label="复制代码"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.5" aria-hidden="true"><rect x="8" y="8" width="12" height="12" rx="2"></rect><path d="M16 8V4a1 1 0 0 0-1-1H4a1 1 0 0 0-1 1v11a1 1 0 0 0 1 1h4"></path></svg><span>复制</span></button></div>

<h2 id="五启动-hermes-dashboard">五、启动 Hermes Dashboard</h2>
<p>Tunnel 转发时，HTTP 请求的 <code>Host</code> 为公网域名，而非 <code>localhost</code>。Hermes 默认仅接受本机 Host，未调整时易出现 <strong>502</strong>。</p>
<div class="code-block"><pre><code class="hljs language-bash">hermes dashboard --stop

hermes dashboard --host 0.0.0.0 --insecure --no-open
</code></pre><button type="button" class="code-copy" data-copy-code="" aria-label="复制代码"><svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.5" aria-hidden="true"><rect x="8" y="8" width="12" height="12" rx="2"></rect><path d="M16 8V4a1 1 0 0 0-1-1H4a1 1 0 0 0-1 1v11a1 1 0 0 0 1 1h4"></path></svg><span>复制</span></button></div>
<p>参数说明：</p>
<ul>
<li><code>--host 0.0.0.0</code>：监听所有网卡（默认仅 <code>127.0.0.1</code>）</li>
<li><code>--insecure</code>：允许非 localhost 的 Host（经 Tunnel 访问时必需）</li>
<li><code>--no-open</code>：服务器上不自动打开浏览器</li>
</ul>
<p>日常重启可记一条：</p>
<div class="code-block"><pre><code class="hljs language-bash">hermes dashboard --stop &#x26;&#x26; hermes dashboard --host 0.0.0.0 --insecure --no-open

<h2 id="六配置-cloudflare-access访问控制">六、配置 Cloudflare Access（访问控制）</h2>
<p>隧道建立后，域名对公网可达，<strong>必须</strong>增加认证层。</p>
<p>操作入口：</p>
<p><a href="https://one.dash.cloudflare.com/" rel="noopener noreferrer">https://one.dash.cloudflare.com/</a></p>
<p>路径：<strong>Zero Trust → Access → Applications → Add an application → Self-hosted</strong></p>
<p><img src="https://assets.musecanto.com/uvxwY7KW9sGYbUfSojyke/sv-books/2026_06_01_editorimg_711f68d2-c8ad-4ad5-8257-c794483b50b1.png" alt="image" loading="lazy" decoding="async"></p>
<p>建议配置：</p>
<ul>
<li><strong>Application name</strong>：Hermes Dashboard（自定）</li>
<li><strong>Application domain</strong>：<code>hermes.&#x3C;你的域名></code></li>
<li><strong>Session duration</strong>：24 小时（可按需调整）</li>
<li><strong>Policy</strong>：Action 选 Allow；Include 选 <strong>Emails</strong>，仅填写本人邮箱</li>
</ul>
<p>效果：访问 <code>https://hermes.&#x3C;你的域名></code> 时先出现 Cloudflare 登录页，通过策略后才进入 Dashboard。</p>
<p><img src="https://assets.musecanto.com/uvxwY7KW9sGYbUfSojyke/sv-books/2026_06_01_editorimg_e94a449e-13f2-40bf-9e91-1b4b136c9e99.png" alt="image" loading="lazy" decoding="async"></p>
<blockquote>
<p>访问域名出现Cloudflare的鉴权页面，上述就是Cloudfalre Access生效的情况</p>
</blockquote>
